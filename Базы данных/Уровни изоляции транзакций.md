
# 1. Аномалии чтения


### 1.1. Dirty Read

Транзакция читает изменения другой транзакции, которые ещё не были зафиксированы


### 1.2. Non-Repeatable Read

Одна транзакция дважды читает одну строку и получает разные значения

```
T1 читает balance = 100
T2 изменяет balance = 200 и делает COMMIT
T1 повторно читает balance = 200
```


### 1.3. Phantom Read

Повторный запрос по условию возвращает другой набор строк

```
T1 читает все заказы со status = 'new'
T2 добавляет подходящий заказ и делает COMMIT
T1 повторяет запрос и видит новую строку
```


### 1.4. Write Skew (доп.)

Две транзакции читают пересекающиеся данные, изменяют разные строки и совместно нарушают бизнес-инвариант

Допустим, хотя бы один врач должен оставаться на дежурстве:

```
doctor_A = on
doctor_B = on
```

Конкурентное выполнение:

```
T1 читает: A = on, B = on
T2 читает: A = on, B = on

T1 изменяет A = off
T2 изменяет B = off

T1 делает COMMIT
T2 делает COMMIT
```

Итог:

```
doctor_A = off
doctor_B = off
```

Прямого конфликта записи нет, потому что транзакции изменяют разные строки, но общий инвариант нарушен

# 2. Уровни изоляции

|Уровень|Dirty Read|Non-Repeatable Read|Phantom Read|Write Skew|
|---|---|---|---|---|
|`Read Uncommitted`|возможен|возможен|возможен|возможен|
|`Read Committed`|запрещён|возможен|возможен|возможен|
|`Repeatable Read`|запрещён|запрещён|возможен|возможен|
|`Serializable`|запрещён|запрещён|запрещён|запрещён|

### 2.1. Read Uncommitted

Транзакция может читать незакоммиченные изменения других транзакций

- минимальная изоляция
- высокая конкурентность
- возможны все три аномалии


### 2.2. Read Committed

Каждый запрос читает только зафиксированные данные

- исключает Dirty Read
- часто используется как уровень по умолчанию


### 2.3. Repeatable Read

Повторное чтение уже прочитанных строк возвращает те же значения

- исключает Dirty Read
- исключает Non-Repeatable Read
- по стандарту допускает Phantom Read
- может допускать Write Skew, потому что (например в pg) стабильный snapshot не обнаруживает логические конфликты между изменениями разных строк

### 2.4. Serializable

Результат эквивалентен последовательному выполнению транзакций

- максимальная изоляция
- исключает три классические аномалии
- исключает Write Skew
- снижает конкурентность
- возможны блокировки, конфликты и повторное выполнение транзакций


> Реальное поведение зависит от конкретной СУБД и реализации MVCC, поэтому `Repeatable Read` в некоторых базах предотвращает больше аномалий, чем требует стандарт SQL
