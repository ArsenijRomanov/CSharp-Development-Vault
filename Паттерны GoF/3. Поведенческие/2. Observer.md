Паттерн "Наблюдатель" (Observer) представляет поведенческий шаблон проектирования, который использует отношение "один ко многим". В этом отношении есть один наблюдаемый объект и множество наблюдателей. И при изменении наблюдаемого объекта автоматически происходит оповещение всех наблюдателей.

Данный паттерн еще называют Publisher-Subscriber (издатель-подписчик).

### Когда использовать паттерн Наблюдатель?

- Когда система состоит из множества классов, объекты которых должны находиться в согласованных состояниях
    
- Когда общая схема взаимодействия объектов предполагает две стороны: одна рассылает сообщения и является главным, другая получает сообщения и реагирует на них. Отделение логики обеих сторон позволяет их рассматривать независимо и использовать отдельно друга от друга.
    
- Когда существует один объект, рассылающий сообщения, и множество подписчиков, которые получают сообщения. При этом точное число подписчиков заранее неизвестно и процессе работы программы может изменяться.

## Участники паттерна

- **IObservable** — объявляет операции добавления, удаления и уведомления наблюдателей
- **ConcreteObservable** — реализует `IObservable`, хранит коллекцию наблюдателей и рассылает им уведомления
- **IObserver** — объявляет общий контракт получения уведомления
- **ConcreteObserver** — реализует конкретную реакцию на уведомление

---

## Формальное представление на C\#

### 1. IObserver

Определяет общий контракт наблюдателей

```cs
public interface IObserver
{
    void Update();
}
```

Наблюдаемый объект работает только с интерфейсом `IObserver` и не зависит от конкретных реализаций наблюдателей

---

### 2. ConcreteObserver

Реализует конкретную реакцию на уведомление

```cs
public sealed class ConcreteObserver : IObserver
{
    public ConcreteObserver()
    {
    }

    public void Update()
    {
        Console.WriteLine(
            "ConcreteObserver получил уведомление");
    }
}
```

Разные реализации `IObserver` могут по-разному реагировать на одно и то же уведомление

---

### 3. IObservable

Определяет контракт наблюдаемого объекта

```cs
public interface IObservable
{
    void AddObserver(IObserver observer);

    void RemoveObserver(IObserver observer);

    void NotifyObservers();
}
```

Интерфейс позволяет:

- зарегистрировать наблюдателя
- удалить наблюдателя
- уведомить всех зарегистрированных наблюдателей

---

### 4. ConcreteObservable

Хранит коллекцию наблюдателей и реализует управление подписками

```cs
public sealed class ConcreteObservable : IObservable
{
    private readonly List<IObserver> _observers;

    public ConcreteObservable()
    {
        _observers = [];
    }

    public void AddObserver(IObserver observer)
    {
        _observers.Add(observer);
    }

    public void RemoveObserver(IObserver observer)
    {
        _observers.Remove(observer);
    }

    public void NotifyObservers()
    {
        foreach (IObserver observer in _observers)
        {
            observer.Update();
        }
    }
}
```

`ConcreteObservable` не знает конкретных типов наблюдателей. Он хранит их через общий интерфейс:

```cs
private readonly List<IObserver> _observers;
```

При вызове `NotifyObservers()` наблюдаемый объект вызывает метод `Update()` у каждого зарегистрированного наблюдателя

# Push- и Pull-модели уведомления

В Observer данные об изменении можно передавать наблюдателям двумя основными способами

### Push model

Наблюдаемый объект сам передаёт наблюдателю необходимые данные

```cs
public interface IObserver
{
    void Update(int newState);
}
```

```cs
public void NotifyObservers()
{
    foreach (IObserver observer in _observers)
    {
        observer.Update(_state);
    }
}
```

Особенности:

- наблюдатель сразу получает данные об изменении
- не требуется дополнительный запрос к наблюдаемому объекту
- `IObservable` определяет, какие именно данные получат все наблюдатели
- разным наблюдателям могут передаваться ненужные данные
- изменение формата уведомления может потребовать изменения интерфейса `IObserver`

---

### Pull model

Наблюдаемый объект передаёт только сигнал об изменении, а наблюдатель самостоятельно запрашивает нужные данные

```cs
public interface IObserver
{
    void Update();
}
```

Наблюдатель должен иметь ссылку на наблюдаемый объект:

```cs
public sealed class ConcreteObserver : IObserver
{
    private readonly ConcreteObservable _observable;

    public ConcreteObserver(ConcreteObservable observable)
    {
        _observable = observable;
    }

    public void Update()
    {
        int state = _observable.State;

        Console.WriteLine(
            $"Получено новое состояние: {state}");
    }
}
```

Уведомление:

```cs
public void NotifyObservers()
{
    foreach (IObserver observer in _observers)
    {
        observer.Update();
    }
}
```

Особенности:

- наблюдатель сам решает, какие данные ему нужны
- интерфейс `IObserver` остаётся простым
- наблюдатель сильнее связан с API наблюдаемого объекта
- получение данных требует дополнительных обращений
- между уведомлением и чтением состояние теоретически может успеть измениться

---

## Гибридный вариант

На практике часто передают не всё состояние объекта, а специальный объект события:

```cs
public interface IObserver
{
    void Update(StateChangedEvent notification);
}
```

```cs
public sealed record StateChangedEvent(
    int OldValue,
    int NewValue);
```

Такой подход близок к Push model, но наблюдателю передаётся только информация о конкретном событии, а не весь объект или всё его состояние. Именно по такому принципу обычно устроены события в .NET через `EventArgs`

---

# Реализация Observer через события C#

В C# паттерн Observer обычно реализуется с помощью:

- делегатов
- событий `event`
- подписки через `+=`
- отписки через `-=`

При этом отдельные интерфейсы `IObservable` и `IObserver` обычно не требуются: их роль берёт на себя контракт события

---

## Данные события

Создаётся объект, содержащий данные об изменении:

```cs
public sealed class StateChangedEventArgs : EventArgs
{
    public int OldState { get; }

    public int NewState { get; }

    public StateChangedEventArgs(
        int oldState,
        int newState)
    {
        OldState = oldState;
        NewState = newState;
    }
}
```

Это push-модель: наблюдаемый объект сам передаёт подписчикам старое и новое состояние

---

## Наблюдаемый объект

```cs
public sealed class ConcreteObservable
{
    private int _state;

    public event EventHandler<StateChangedEventArgs>? StateChanged;

    public int State
    {
        get => _state;

        set
        {
            if (_state == value)
                return;

            int oldState = _state;
            _state = value;

            OnStateChanged(oldState, value);
        }
    }

    private void OnStateChanged(
        int oldState,
        int newState)
    {
        StateChanged?.Invoke(
            this,
            new StateChangedEventArgs(
                oldState,
                newState));
    }
}
```

Объявление события:

```cs
public event EventHandler<StateChangedEventArgs>? StateChanged;
```

`EventHandler<TEventArgs>` представляет делегат следующей формы:

```cs
void Handler(
    object? sender,
    StateChangedEventArgs e);
```

- `sender` — объект, вызвавший событие
- `e` — данные события

Вызов события:

```cs
StateChanged?.Invoke(this, eventArgs);
```

Оператор `?.` означает, что событие вызывается только при наличии подписчиков

---

## Первый наблюдатель

```cs
public sealed class ConcreteObserver1
{
    public void HandleStateChanged(
        object? sender,
        StateChangedEventArgs e)
    {
        Console.WriteLine(
            $"Observer 1: {e.OldState} -> {e.NewState}");
    }
}
```

## Второй наблюдатель

```cs
public sealed class ConcreteObserver2
{
    public void HandleStateChanged(
        object? sender,
        StateChangedEventArgs e)
    {
        Console.WriteLine(
            $"Observer 2 получил новое состояние: {e.NewState}");
    }
}
```

Наблюдатели не обязаны реализовывать общий интерфейс. Достаточно, чтобы их методы соответствовали сигнатуре делегата `EventHandler<StateChangedEventArgs>`

---

## Подписка и отписка

```cs
var observable = new ConcreteObservable();

var firstObserver = new ConcreteObserver1();
var secondObserver = new ConcreteObserver2();

observable.StateChanged +=
    firstObserver.HandleStateChanged;

observable.StateChanged +=
    secondObserver.HandleStateChanged;

observable.State = 10;
```

После изменения состояния будут последовательно вызваны оба обработчика

Отписка выполняется через `-=`:

```cs
observable.StateChanged -=
    firstObserver.HandleStateChanged;

observable.State = 20;
```

Теперь уведомление получит только `secondObserver`
