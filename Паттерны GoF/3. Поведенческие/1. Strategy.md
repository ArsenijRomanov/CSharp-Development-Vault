**Стратегия** — поведенческий паттерн, который определяет семейство взаимозаменяемых алгоритмов, инкапсулирует каждый из них в отдельном классе и позволяет подменять алгоритм независимо от использующего его объекта

## Проблема

Без паттерна разные варианты алгоритма часто находятся внутри одного класса:

```cs
public void Execute(string algorithmType)
{
    if (algorithmType == "first")
    {
        // первый алгоритм
    }
    else if (algorithmType == "second")
    {
        // второй алгоритм
    }
}
```

При добавлении нового алгоритма приходится изменять существующий класс

Это приводит к:

- разрастанию условных конструкций
- смешиванию нескольких алгоритмов в одном классе
- усложнению тестирования
- нарушению **Open-Closed Principle**
- невозможности независимо переиспользовать алгоритмы

Strategy выносит каждый алгоритм в отдельную реализацию общего контракта

## Участники паттерна

- **Strategy** - объявляет общий контракт для всех поддерживаемых алгоритмов
- **ConcreteStrategy** - реализует конкретный вариант алгоритма
- **Context** - хранит ссылку на стратегию и делегирует ей выполнение алгоритма
- **Client** - создаёт конкретную стратегию и передаёт её контексту

## Формальное определение на C\#

### 1. Strategy

Объявляет общий контракт для всех поддерживаемых алгоритмов

```cs
public interface IStrategy
{
    void Algorithm();
}
```

Контекст работает только с этим интерфейсом и не зависит от конкретных реализаций

### 2. ConcreteStrategy

```cs
public sealed class ConcreteStrategy1 : IStrategy
{
    public void Algorithm()
    {
        Console.WriteLine(
            "Выполняется алгоритм первой стратегии");
    }
}
```

```cs
public sealed class ConcreteStrategy2 : IStrategy
{
    public void Algorithm()
    {
        Console.WriteLine(
            "Выполняется алгоритм второй стратегии");
    }
}
```

Все конкретные стратегии должны быть взаимозаменяемы с точки зрения контекста

### 3. Context

```cs
public sealed class Context
{
    private IStrategy _strategy;

    public Context(IStrategy strategy)
    {
        _strategy = strategy;
    }

    public void SetStrategy(IStrategy strategy)
    {
        _strategy = strategy;
    }

    public void ExecuteAlgorithm()
    {
        _strategy.Algorithm();
    }
}
```

Контекст отвечает за основную логику, но не знает деталей конкретного алгоритма

---

### 4. Client

```cs
public static class Client
{
    public static void Main()
    {
        var context = new Context(
            new ConcreteStrategy1());

        context.ExecuteAlgorithm();

        context.SetStrategy(
            new ConcreteStrategy2());

        context.ExecuteAlgorithm();
    }
}
```

Клиент определяет, какой алгоритм должен использоваться

# Примеры из лаб

## Алгоритма имитации отжига для решения задача коммивояжера

В задаче коммивояжёра требуется найти маршрут минимальной стоимости, проходящий через все вершины графа. Имитация отжига решает эту задачу путём постепенного изменения текущего маршрута и вероятностного принятия некоторых ухудшающих решений

### Основные шаги алгоритма

1. Построить начальный маршрут
2. Вычислить его стоимость
3. Определить начальную температуру
4. Сгенерировать соседний маршрут на основе текущего
5. Вычислить стоимость нового маршрута
6. Принять новый маршрут, если он лучше, либо с некоторой вероятностью, если он хуже
7. Уменьшить температуру
8. Повторять процесс до выполнения критерия остановки

### Применение Strategy

Отдельные шаги алгоритма могут выполняться разными способами, поэтому они выносятся в самостоятельные стратегии:

- **Построение начального маршрута** — случайная перестановка, жадный алгоритм, маршрут ближайшего соседа
	
- **Генерация соседнего решения** — перестановка двух вершин, вставка вершины, `2-opt`
	
- **Оценка маршрута** — обычная сумма весов либо оценка со штрафами за недопустимые переходы
	
- **Определение начальной температуры** — фиксированное значение либо автоматическая оценка
	
- **Охлаждение** — геометрический закон, охлаждение Коши и другие формулы
	
- **Критерий остановки** — число итераций, минимальная температура, отсутствие улучшений

### Участники

- Context $\rightarrow$ оркестратор имитации отжига

- Strategy $\rightarrow$ интерфейс отдельного этапа алгоритма

- ConcreteStrategy $\rightarrow$ конкретный способ построения маршрута, генерации соседа, охлаждения или остановки

- Client $\rightarrow$ конфигурация, выбирающая конкретные стратегии

Оркестратор содержит общий порядок выполнения имитации отжига, но не знает деталей отдельных этапов. Благодаря этому алгоритмы выполнения шагов можно заменять и комбинировать без изменения основного цикла решателя.
