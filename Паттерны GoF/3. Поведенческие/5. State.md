**Состояние** — поведенческий паттерн, который позволяет объекту изменять своё поведение при изменении внутреннего состояния

Вместо большого количества проверок:

```cs
if (state == StateA)
{
    // поведение A
}
else if (state == StateB)
{
    // поведение B
}
```

поведение каждого состояния выносится в отдельный класс

`Context`
- хранит текущее State
- делегирует ему выполнение операции

`StateA` / `StateB`
- реализуют поведение для конкретного состояния


## Проблема

По мере увеличения числа состояний условная логика начинает разрастаться:

- одни и те же проверки состояния повторяются в разных методах
- добавление нового состояния требует изменения существующего класса
- правила переходов и поведение разных состояний смешиваются
- класс контекста получает слишком много ответственности

State заменяет условное ветвление полиморфизмом

## Когда применять

Паттерн подходит, когда:

- поведение объекта существенно зависит от его текущего состояния
- существует несколько явно выделенных состояний
- для каждого состояния допустимы разные операции
- переходы между состояниями образуют конечный автомат
- код содержит большое количество `if`, `switch` или проверок enum-состояния

# Формальное представление

## State

`State` определяет общий контракт поведения для всех состояний

На диаграмме это базовый класс с методом:

```cs
Handle(Context context)
```

```cs
public abstract class State
{
    protected State()
    {
    }

    public abstract void Handle(Context context);
}
```

Ссылка на `Context` позволяет состоянию:

- работать с данными контекста
- изменять его состояние
- выполнять переход в другое состояние


## Context

`Context` хранит текущее состояние и делегирует ему выполнение запроса

```cs
public sealed class Context
{
    public State State { get; set; }

    public Context(State state)
    {
        State = state;
    }

    public void Request()
    {
        State.Handle(this);
    }
}
```

`Context` не реализует поведение каждого состояния самостоятельно

Он знает только текущее значение `State` и вызывает общий метод:

```cs
State.Handle(this);
```


## StateA

`StateA` реализует поведение объекта в состоянии A

```cs
public sealed class StateA : State
{
    public StateA()
    {
    }

    public override void Handle(Context context)
    {
        Console.WriteLine("Выполняется поведение состояния A");

        context.State = new StateB();
    }
}
```

После выполнения состояние может оставить контекст без изменений либо перевести его в другое состояние


## StateB

`StateB` реализует поведение объекта в состоянии B

```cs
public sealed class StateB : State
{
    public StateB()
    {
    }

    public override void Handle(Context context)
    {
        Console.WriteLine("Выполняется поведение состояния B");

        context.State = new StateA();
    }
}
```
