**Команда** — поведенческий паттерн, который превращает запрос на выполнение операции в отдельный объект

Объект команды инкапсулирует:

- какую операцию нужно выполнить
- над каким объектом её выполнить
- какие параметры использовать

Благодаря этому отправитель запроса не зависит от объекта, который фактически выполняет операцию

## Проблема

Без паттерна объект-инициатор напрямую вызывает конкретный сервис:

```cs
public sealed class Invoker
{
    private readonly Receiver _receiver;

    public Invoker(Receiver receiver)
    {
        _receiver = receiver;
    }

    public void Invoke()
    {
        _receiver.Operation("value");
    }
}
```

`Invoker` знает:

- какой объект выполняет операцию
- какой метод нужно вызвать
- какие параметры ему передать

Из-за этого запрос сложно:

- сохранить для отложенного выполнения
- поставить в очередь
- повторить
- отменить
- журналировать
- передать другому исполнителю
- объединить с другими запросами

Command выносит вызов операции в самостоятельный объект

## Когда применять

Паттерн подходит, когда:

- отправителя запроса нужно отделить от исполнителя
- операцию необходимо представить как объект
- запросы нужно ставить в очередь или выполнять позже
- требуется хранить историю операций
- необходимо реализовать повторное выполнение
- требуется отмена операции через `Undo`
- нужно собирать несколько команд в составную операцию
- один инициатор должен уметь запускать разные действия через общий контракт

## Участники паттерна

- **Command** — объявляет общий контракт выполнения команды
- **ConcreteCommand** — хранит параметры запроса и делегирует выполнение получателю
- **Receiver** — содержит фактическую бизнес-логику выполнения операции
- **Invoker** — инициирует выполнение команды через общий контракт
- **Client** — создаёт получателя и команду, после чего передаёт команду инициатору

## Формальное представление на C\#

### 1. Command

Определяет общий контракт команд

```cs
public interface ICommand
{
    void Execute();
}
```

`Invoker` работает только с `ICommand` и не знает, какая конкретная операция будет выполнена


### 2. Receiver

Содержит фактическую реализацию операции

```cs
public sealed class Receiver
{
    public void Operation(string value)
    {
        Console.WriteLine(
            $"Receiver выполняет операцию с параметром: {value}");
    }
}
```

`Receiver` не обязан знать о существовании команды или инициатора

Он предоставляет обычные методы, содержащие полезную логику


### 3. ConcreteCommand

Инкапсулирует запрос и вызывает нужный метод получателя

```cs
public sealed class ConcreteCommand : ICommand
{
    private readonly Receiver _receiver;
    private readonly string _value;

    public ConcreteCommand(
        Receiver receiver,
        string value)
    {
        _receiver = receiver;
        _value = value;
    }

    public void Execute()
    {
        _receiver.Operation(_value);
    }
}
```

Команда хранит:

- Receiver $\rightarrow$ над каким объектом выполнить операцию
- \_value    $\rightarrow$ с какими параметрами выполнить операцию


### 4. Invoker

Хранит или получает команду и инициирует её выполнение

```cs
public sealed class Invoker
{
    private ICommand? _command;

    public void SetCommand(ICommand command)
    {
        _command = command;
    }

    public void Invoke()
    {
        _command?.Execute();
    }
}
```

`Invoker` не знает:

- какой `Receiver` используется
- какой метод получателя будет вызван
- какие параметры содержит команда
- как устроено выполнение операции

Он знает только общий контракт:

```
_command.Execute();
```

---

### 5. Client

Связывает участников паттерна

```cs
public static class Client
{
    public static void Main()
    {
        var receiver = new Receiver();

        ICommand command =
            new ConcreteCommand(
                receiver,
                "value");

        var invoker = new Invoker();

        invoker.SetCommand(command);
        invoker.Invoke();
    }
}
```
