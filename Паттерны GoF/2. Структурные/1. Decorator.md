**Декоратор** — структурный паттерн, который позволяет динамически добавлять объекту новое поведение, помещая его внутрь другого объекта с тем же контрактом

## Когда применять

Decorator подходит, когда:

- поведение нужно добавлять без изменения основного класса
- поведение должно комбинироваться в разных вариантах
- наследование приводит к большому количеству подклассов
- сквозную логику нужно вынести из бизнес-сервиса
- обёртки должны подключаться через конфигурацию или DI
- клиент должен продолжать работать через тот же интерфейс

Типичные декораторы:

```
логирование
метрики
валидация
кэширование
retry
авторизация
транзакции
трассировка
обработка ошибок
```

# Преимущества

- добавляет поведение без изменения исходного класса
- заменяет наследование композицией
- позволяет комбинировать обязанности
- поддерживает OCP
- сохраняет общий интерфейс компонента
- позволяет подключать и удалять поведение независимо
- упрощает выделение сквозной логики

# Структура паттерна

- **Component** — общий контракт
- **ConcreteComponent** — основной объект с базовым поведением
- **Decorator** — хранит ссылку на другой `Component` и делегирует ему вызовы
- **ConcreteDecorator** — добавляет поведение до или после вызова внутреннего объекта

```cs
public interface IOrderService
{
    Task<Order> CreateAsync(
        CreateOrderRequest request,
        CancellationToken cancellationToken);
}
```

Основная реализация:

```cs
public sealed class OrderService : IOrderService
{
    public Task<Order> CreateAsync(
        CreateOrderRequest request,
        CancellationToken cancellationToken)
    {
        // Основная бизнес-логика

        return Task.FromResult(new Order());
    }
}
```

Декоратор логирования:

```cs
public sealed class LoggingOrderService : IOrderService
{
    private readonly IOrderService _inner;
    private readonly ILogger<LoggingOrderService> _logger;

    public LoggingOrderService(
        IOrderService inner,
        ILogger<LoggingOrderService> logger)
    {
        _inner = inner;
        _logger = logger;
    }

    public async Task<Order> CreateAsync(
        CreateOrderRequest request,
        CancellationToken cancellationToken)
    {
        _logger.LogInformation("Creating order");

        Order order = await _inner.CreateAsync(
            request,
            cancellationToken);

        _logger.LogInformation(
            "Order {OrderId} created",
            order.Id);

        return order;
    }
}
```

# Цепочка декораторов

Декораторы можно вкладывать друг в друга:

```cs
IOrderService service =
    new LoggingOrderService(
        new MetricsOrderService(
            new ValidationOrderService(
                new OrderService())),
        logger);
```

# Регистрация через DI

Декоратор можно собрать вручную:

```cs
builder.Services.AddScoped<IOrderService>(provider =>
{
    IOrderService service = new OrderService(
        provider.GetRequiredService<IOrderRepository>());

    service = new ValidationOrderService(service);

    service = new LoggingOrderService(
        service,
        provider.GetRequiredService<
            ILogger<LoggingOrderService>>());

    return service;
});
```

С библиотекой Scrutor декораторы регистрируются отдельно:

```cs
builder.Services.AddScoped<
    IOrderService,
    OrderService>();

builder.Services.Decorate<
    IOrderService,
    ValidationOrderService>();

builder.Services.Decorate<
    IOrderService,
    LoggingOrderService>();
```
