Паттерн Адаптер (Adapter) предназначен для преобразования интерфейса одного класса в интерфейс другого. Благодаря реализации данного паттерна мы можем использовать вместе классы с несовместимыми интерфейсами.

### Когда применять

Adapter подходит, когда:

- нужно использовать сторонний или устаревший класс с несовместимым API
- нельзя изменить исходный класс
- внешний API не должен проникать в бизнес-логику
- требуется заменить библиотеку без изменения клиентов
- нужно преобразовать DTO внешней системы во внутренние модели
- требуется унифицировать несколько разных реализаций под одним контрактом

### Что может преобразовывать адаптер

- интерфейсы
- типы параметров
- форматы данных
- единицы измерения
- возвращаемые значения
- исключения
- синхронные и асинхронные API
- несколько вызовов одного API в одну операцию другого

## Участники

- **Target** — интерфейс, с которым работает клиент
- **Adaptee** — существующий несовместимый класс
- **Adapter** — преобразует вызовы `Target` в вызовы `Adaptee`
- **Client** — использует объект через ожидаемый интерфейс

# Проблема

Приложение ожидает такой контракт:

```cs
public interface IPaymentService
{
    Task PayAsync(
        decimal amount,
        CancellationToken cancellationToken);
}
```

Но сторонняя библиотека предоставляет другой API:

```cs
public sealed class LegacyPaymentClient
{
    public void MakePayment(int amountInCents)
    {
        // Вызов старой платёжной системы
    }
}
```

Интерфейсы несовместимы:

- разные имена методов
- разные типы параметров
- один API асинхронный, другой синхронный
- сумма представлена в разных единицах

Изменять сторонний класс нельзя

# Object Adapter

Наиболее распространённый вариант использует композицию

```cs
public sealed class LegacyPaymentAdapter
    : IPaymentService
{
    private readonly LegacyPaymentClient _client;

    public LegacyPaymentAdapter(
        LegacyPaymentClient client)
    {
        _client = client;
    }

    public Task PayAsync(
        decimal amount,
        CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();

        int amountInCents = checked((int)(amount * 100));

        _client.MakePayment(amountInCents);

        return Task.CompletedTask;
    }
}
```

Использование:

```cs
IPaymentService paymentService =
    new LegacyPaymentAdapter(
        new LegacyPaymentClient());

await paymentService.PayAsync(
    10.50m,
    cancellationToken);
```

Клиент знает только об `IPaymentService` и не зависит от API старой системы

# Адаптер и Anti-Corruption Layer

При интеграции с внешней системой адаптер часто является частью **Anti-Corruption Layer**

```
Внешняя модель
    ↓
Adapter / Mapper
    ↓
Внутренняя модель приложения
```

Это не позволяет внешним DTO, enum, исключениям и правилам распространиться по бизнес-коду

Например, вместо зависимости домена от Kafka-сообщения:

```cs
public Task HandleAsync(
    ExternalOrderCreatedMessage message)
```

создаётся преобразование:

```cs
OrderCreated domainEvent =
    adapter.Adapt(message);
```

После этого бизнес-логика работает только со своей моделью
