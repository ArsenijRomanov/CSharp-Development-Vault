**Мост** — структурный паттерн, который разделяет одну сущность на две независимые иерархии:

- **абстракцию** — высокоуровневое поведение
- **реализацию** — низкоуровневый механизм выполнения

Абстракция не наследует конкретную реализацию, а содержит её через композицию, таким образом и абстракцию, и реализацию можно изменять независимо друг от друга.

### Участники

- **Abstraction**: определяет базовый интерфейс и хранит ссылку на объект Implementor. Выполнение операций в Abstraction делегируется методам объекта Implementor
    
- **RefinedAbstraction**: уточненная абстракция, наследуется от Abstraction и расширяет унаследованный интерфейс
    
- **Implementor**: определяет базовый интерфейс для конкретных реализаций. Как правило, Implementor определяет только примитивные операции. Более сложные операции, которые базируются на примитивных, определяются в Abstraction
    
- **ConcreteImplementorA** и **ConcreteImplementorB**: конкретные реализации, которые унаследованы от Implementor
    
- **Client**: использует объекты Abstraction

## Формальное представление паттерна Bridge на C#

### Implementor

Определяет контракт низкоуровневой реализации

```cs
public abstract class Implementor
{
    public abstract void OperationImp();
}
```

### ConcreteImplementor

Конкретные варианты реализации

```cs
public sealed class ConcreteImplementorA : Implementor
{
    public override void OperationImp()
    {
        Console.WriteLine(
            "ConcreteImplementorA выполняет операцию");
    }
}
```

```cs
public sealed class ConcreteImplementorB : Implementor
{
    public override void OperationImp()
    {
        Console.WriteLine(
            "ConcreteImplementorB выполняет операцию");
    }
}
```

### Abstraction

Определяет высокоуровневый интерфейс и содержит ссылку на `Implementor`

Именно эта ссылка является мостом между двумя иерархиями

```cs
public abstract class Abstraction
{
    protected readonly Implementor Implementor;

    protected Abstraction(Implementor implementor)
    {
        Implementor = implementor;
    }

    public virtual void Operation()
    {
        Implementor.OperationImp();
    }
}
```

`Abstraction` не выполняет низкоуровневую операцию самостоятельно, а делегирует её объекту `Implementor`

### RefinedAbstraction

Расширяет высокоуровневое поведение, не привязываясь к конкретной реализации

```cs
public sealed class RefinedAbstraction : Abstraction
{
    public RefinedAbstraction(Implementor implementor)
        : base(implementor)
    {
    }

    public override void Operation()
    {
        Console.WriteLine(
            "RefinedAbstraction выполняет высокоуровневую логику");

        Implementor.OperationImp();
    }
}
```

### Client

Клиент независимо выбирает вариант абстракции и вариант реализации

```cs
public static class Client
{
    public static void Main()
    {
        Abstraction first =
            new RefinedAbstraction(
                new ConcreteImplementorA());

        first.Operation();

        Abstraction second =
            new RefinedAbstraction(
                new ConcreteImplementorB());

        second.Operation();
    }
}
```

## Пример: уведомления и каналы доставки

Допустим, существуют два типа уведомлений:

- обычное
- срочное

И несколько каналов доставки:

- `Email`
- `SMS`
- `Telegram`

При использовании только наследования быстро появляется комбинационный взрыв:

```cs
EmailNotification
SmsNotification
TelegramNotification

UrgentEmailNotification
UrgentSmsNotification
UrgentTelegramNotification
```

При добавлении нового типа уведомления приходится создавать класс для каждого канала

```
Количество классов ≈ типы уведомлений × каналы доставки
```

Bridge разделяет эти две оси изменений:

- Тип уведомления $\rightarrow$ `Notification`
- Способ доставки $\rightarrow$ `INotificationSender`

### Implementor

```cs
public interface INotificationSender
{
    Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken);
}
```

### ConcreteImplementor

```cs
public sealed class EmailSender : INotificationSender
{
    public Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            $"Email to {recipient}: {message}");

        return Task.CompletedTask;
    }
}
```

```cs
public sealed class SmsSender : INotificationSender
{
    public Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            $"SMS to {recipient}: {message}");

        return Task.CompletedTask;
    }
}
```

### Abstraction

```cs
public abstract class Notification
{
    protected Notification(
        INotificationSender sender)
    {
        Sender = sender;
    }

    protected INotificationSender Sender { get; }

    public abstract Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken);
}
```

### RefinedAbstraction

Обычное уведомление:

```cs
public sealed class RegularNotification : Notification
{
    public RegularNotification(
        INotificationSender sender)
        : base(sender)
    {
    }

    public override Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken)
    {
        return Sender.SendAsync(
            recipient,
            message,
            cancellationToken);
    }
}
```

Срочное уведомление:

```cs
public sealed class UrgentNotification : Notification
{
    public UrgentNotification(
        INotificationSender sender)
        : base(sender)
    {
    }

    public override Task SendAsync(
        string recipient,
        string message,
        CancellationToken cancellationToken)
    {
        return Sender.SendAsync(
            recipient,
            $"URGENT: {message}",
            cancellationToken);
    }
}
```

Использование:

```
Notification notification =
    new UrgentNotification(
        new SmsSender());

await notification.SendAsync(
    "+79990000000",
    "Payment failed",
    cancellationToken);
```

Можно свободно комбинировать обе иерархии:

```cs
new RegularNotification(new EmailSender());
new RegularNotification(new SmsSender());

new UrgentNotification(new EmailSender());
new UrgentNotification(new SmsSender());
```
