**Прокси** — структурный паттерн, который предоставляет объект-заместитель с тем же контрактом, что и реальный объект, и контролирует доступ к нему

Клиент работает с прокси так, будто это настоящий объект:

```cs
IReportService service = new ReportServiceProxy(...);

Report report = await service.GetAsync(id);
```

Прокси может перед вызовом реального объекта:

- проверить права доступа
- выполнить ленивую инициализацию
- обратиться к удалённому сервису
- проверить кэш
- ограничить количество вызовов
- управлять соединением
- логировать обращение
- повторить неудачную операцию

---

    C[Client] --> I[ISubject]

## Участники паттерна

- **Subject** — общий контракт прокси и реального объекта
- **RealSubject** — настоящий объект, выполняющий основную работу
- **Proxy** — контролирует доступ к `RealSubject`
- **Client** — работает через общий контракт

```cs
public interface IDocumentService
{
    Task<Document> GetAsync(
        Guid id,
        CancellationToken cancellationToken);
}
```

Реальный объект:

```cs
public sealed class DocumentService : IDocumentService
{
    public Task<Document> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        // Получение документа

        return Task.FromResult(new Document(id));
    }
}
```

Прокси:

```cs
public sealed class DocumentServiceProxy : IDocumentService
{
    private readonly IDocumentService _realService;

    public DocumentServiceProxy(
        IDocumentService realService)
    {
        _realService = realService;
    }

    public Task<Document> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        // Контроль доступа к реальному объекту

        return _realService.GetAsync(
            id,
            cancellationToken);
    }
}
```

# 1. Виртуальный прокси

**Virtual Proxy** откладывает создание дорогого объекта до момента первого использования

```cs
public interface IReportGenerator
{
    Report Generate();
}
```

```cs
public sealed class PdfReportGenerator
    : IReportGenerator
{
    public PdfReportGenerator()
    {
        // Дорогая инициализация
    }

    public Report Generate()
    {
        return new Report();
    }
}
```

Прокси:

```cs
public sealed class LazyReportGenerator
    : IReportGenerator
{
    private readonly Lazy<PdfReportGenerator> _generator;

    public LazyReportGenerator()
    {
        _generator = new Lazy<PdfReportGenerator>(
            () => new PdfReportGenerator());
    }

    public Report Generate()
    {
        return _generator.Value.Generate();
    }
}
```

## Практические сценарии

- загрузка большого документа только при обращении к содержимому
- открытие соединения только при первой операции
- инициализация тяжёлого SDK
- загрузка изображения или файла по требованию
- ленивое получение связанной сущности из базы данных

# 2. Удалённый прокси

**Remote Proxy** представляет объект, который фактически находится в другом процессе или на другом сервере

Клиент вызывает обычный метод:

```cs
UserResponse response =
    await userClient.GetUserAsync(request);
```

Прокси внутри:
  $\rightarrow$ сериализует параметры
  $\rightarrow$ отправляет запрос по сети
  $\rightarrow$ ожидает ответ
  $\rightarrow$ десериализует результат
  $\rightarrow$ возвращает объект клиенту

Пример контракта:

```cs
public interface IUserService
{
    Task<User> GetAsync(
        Guid id,
        CancellationToken cancellationToken);
}
```

Удалённый прокси:

```cs
public sealed class GrpcUserServiceProxy
    : IUserService
{
    private readonly Users.UsersClient _client;

    public GrpcUserServiceProxy(
        Users.UsersClient client)
    {
        _client = client;
    }

    public async Task<User> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        UserReply reply =
            await _client.GetUserAsync(
                new UserRequest
                {
                    Id = id.ToString()
                },
                cancellationToken:
                    cancellationToken);

        return new User(
            Guid.Parse(reply.Id),
            reply.Name);
    }
}
```

Клиент зависит от `IUserService` и не знает, выполняется операция локально или через gRPC

## Где встречается

- gRPC-клиенты
- REST SDK
- WCF-клиенты
- RPC-фреймворки
- клиенты микросервисов
- клиенты брокеров и распределённых хранилищ

Сгенерированный gRPC-клиент можно рассматривать как технологический remote proxy: вызов метода преобразуется в сетевой RPC-запрос

# 3. Защитный прокси

**Protection Proxy** проверяет, имеет ли клиент право выполнить операцию

```cs
public sealed class SecuredDocumentService
    : IDocumentService
{
    private readonly IDocumentService _inner;
    private readonly ICurrentUser _currentUser;
    private readonly IAuthorizationService _authorization;

    public SecuredDocumentService(
        IDocumentService inner,
        ICurrentUser currentUser,
        IAuthorizationService authorization)
    {
        _inner = inner;
        _currentUser = currentUser;
        _authorization = authorization;
    }

    public async Task<Document> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        bool allowed =
            await _authorization.CanReadDocumentAsync(
                _currentUser.Id,
                id,
                cancellationToken);

        if (!allowed)
            throw new ForbiddenException();

        return await _inner.GetAsync(
            id,
            cancellationToken);
    }
}
```

## Практические сценарии

- проверка ролей и разрешений
- доступ к административным операциям
- ограничение доступа к файлам
- проверка tenant
- проверка подписки или тарифного плана
- доступ к платным функциям

# 4. Кэширующий прокси

Кэширующий прокси сначала проверяет кэш и обращается к реальному объекту только при отсутствии результата

```cs
public sealed class CachedProductService
    : IProductService
{
    private readonly IProductService _inner;
    private readonly ICache _cache;

    public CachedProductService(
        IProductService inner,
        ICache cache)
    {
        _inner = inner;
        _cache = cache;
    }

    public async Task<Product?> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        string key = $"product:{id}";

        Product? cached =
            await _cache.GetAsync<Product>(
                key,
                cancellationToken);

        if (cached is not null)
            return cached;

        Product? product =
            await _inner.GetAsync(
                id,
                cancellationToken);

        if (product is not null)
        {
            await _cache.SetAsync(
                key,
                product,
                cancellationToken);
        }

        return product;
    }
}
```

# 5. Прокси ограничения доступа

Прокси может ограничивать частоту вызовов реального объекта

```cs
public sealed class RateLimitedApiProxy : IExternalApi
{
    private readonly IExternalApi _inner;
    private readonly RateLimiter _rateLimiter;

    public async Task<Response> SendAsync(
        Request request,
        CancellationToken cancellationToken)
    {
        using RateLimitLease lease =
            await _rateLimiter.AcquireAsync(
                permitCount: 1,
                cancellationToken);

        if (!lease.IsAcquired)
            throw new RateLimitExceededException();

        return await _inner.SendAsync(
            request,
            cancellationToken);
    }
}
```

Применяется для:

- защиты внешнего API
- ограничения запросов к БД
- контроля обращений к файловой системе
- соблюдения лимитов стороннего сервиса
- ограничения параллелизма

# 6. Прокси повторных попыток

Прокси может повторять временно неудачные операции:

```cs
public sealed class RetryPaymentGateway
    : IPaymentGateway
{
    private readonly IPaymentGateway _inner;

    public async Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        for (int attempt = 1; attempt <= 3; attempt++)
        {
            try
            {
                return await _inner.PayAsync(
                    request,
                    cancellationToken);
            }
            catch (TemporaryPaymentException)
                when (attempt < 3)
            {
                await Task.Delay(
                    TimeSpan.FromMilliseconds(200),
                    cancellationToken);
            }
        }

        throw new InvalidOperationException();
    }
}
```

# 7. Smart Reference Proxy

Прокси может выполнять дополнительное управление объектом при каждом обращении:

- подсчитывать активные ссылки
- открывать и закрывать ресурс
- синхронизировать доступ
- блокировать объект
- собирать метрики использования
- управлять транзакцией

Пример синхронизирующего прокси:

```cs
public sealed class SynchronizedCounter
    : ICounter
{
    private readonly ICounter _inner;
    private readonly object _sync = new();

    public int Increment()
    {
        lock (_sync)
        {
            return _inner.Increment();
        }
    }
}
```

# Отличие от Decorator

Proxy и Decorator часто имеют почти одинаковую структуру:

```cs
public sealed class Wrapper : IService
{
    private readonly IService _inner;
}
```

Различается намерение

- `Decorator` $\rightarrow$ добавляет объекту новую обязанность
-     `Proxy`     $\rightarrow$ контролирует доступ к реальному объекту
