**Фасад** — структурный паттерн, который предоставляет простой единый интерфейс к сложной подсистеме из нескольких классов

![[Pasted image 20260727143423.png]]

Фасад не обязательно заменяет интерфейсы подсистемы. Он скрывает типичный сценарий их совместного использования

## Когда применять

Фасад подходит, когда:

- подсистема содержит много компонентов и сложный порядок вызовов
- клиентам нужен небольшой набор типичных операций
- нужно скрыть инфраструктурные детали
- требуется уменьшить связанность между слоями
- несколько клиентов повторяют одну и ту же последовательность действий
- внутреннюю реализацию подсистемы нужно менять независимо от клиентов

## Проблема

Допустим, для оформления заказа необходимо:

- проверить товарные остатки
- рассчитать стоимость
- провести оплату
- зарезервировать товары
- создать доставку
- отправить уведомление

Без фасада клиент управляет всеми компонентами самостоятельно:

```cs
await inventory.CheckAsync(order);
Money total = pricing.Calculate(order);
Payment payment = await payments.PayAsync(total);
await inventory.ReserveAsync(order);
Delivery delivery = await deliveryService.CreateAsync(order);
await notifications.SendOrderCreatedAsync(order);
```

Клиент знает:

- какие сервисы участвуют в операции
- в каком порядке их вызывать
- какие данные передавать между ними
- как обрабатывать частичные ошибки

При изменении сценария приходится менять всех клиентов

## Реализация фасада

```cs
public interface ICheckoutFacade
{
    Task<OrderResult> CheckoutAsync(
        Order order,
        CancellationToken cancellationToken);
}
```

```cs
public sealed class CheckoutFacade : ICheckoutFacade
{
    private readonly IInventoryService _inventory;
    private readonly IPricingService _pricing;
    private readonly IPaymentService _payments;
    private readonly IDeliveryService _delivery;
    private readonly INotificationService _notifications;

    public CheckoutFacade(
        IInventoryService inventory,
        IPricingService pricing,
        IPaymentService payments,
        IDeliveryService delivery,
        INotificationService notifications)
    {
        _inventory = inventory;
        _pricing = pricing;
        _payments = payments;
        _delivery = delivery;
        _notifications = notifications;
    }

    public async Task<OrderResult> CheckoutAsync(
        Order order,
        CancellationToken cancellationToken)
    {
        await _inventory.CheckAsync(
            order,
            cancellationToken);

        Money total = _pricing.Calculate(order);

        Payment payment = await _payments.PayAsync(
            total,
            cancellationToken);

        await _inventory.ReserveAsync(
            order,
            cancellationToken);

        Delivery delivery = await _delivery.CreateAsync(
            order,
            cancellationToken);

        await _notifications.SendOrderCreatedAsync(
            order,
            cancellationToken);

        return new OrderResult(
            payment.Id,
            delivery.Id,
            total);
    }
}
```

Клиент теперь вызывает одну операцию:

```cs
OrderResult result =
    await checkoutFacade.CheckoutAsync(
        order,
        cancellationToken);
```

## Что делает фасад

Фасад может:

- объединять несколько вызовов в одну операцию
- определять порядок работы компонентов
- преобразовывать данные между частями подсистемы
- скрывать технические детали
- предоставлять удобный API для типичных сценариев
- централизовать обработку ошибок и транзакционную координацию

## Фасад и слоистая архитектура

Сервис прикладного слоя часто выполняет роль фасада над доменными и инфраструктурными компонентами:

```cs
public sealed class CreateOrderHandler
{
    private readonly IOrderRepository _orders;
    private readonly IPaymentGateway _payments;
    private readonly IEventPublisher _events;

    public async Task HandleAsync(
        CreateOrder command,
        CancellationToken cancellationToken)
    {
        // Координация сценария
    }
}
```

Такой обработчик предоставляет внешнему слою одну операцию и скрывает внутреннюю реализацию use case
