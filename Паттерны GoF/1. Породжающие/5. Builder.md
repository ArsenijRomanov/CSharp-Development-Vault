**Строитель** — порождающий паттерн, который отделяет пошаговое создание сложного объекта от его итогового представления

Объект создаётся не одним большим конструктором, а последовательностью шагов.

## Когда применять

Builder подходит, когда:

- объект имеет много параметров
- многие параметры необязательны
- объект создаётся по нескольким шагам
- нужно исключить телескопические конструкторы
- необходимо создавать разные представления одним процессом
- перед созданием требуется валидация конфигурации
- итоговый объект должен быть неизменяемым

## Проблема

При большом количестве параметров конструктор становится неудобным:

```cs
var request = new Request(
    "https://example.com",
    "POST",
    30,
    true,
    "application/json",
    token,
    body,
    headers);
```

Непонятно, что означает каждый аргумент, а большинство параметров могут быть необязательными

Builder позволяет собирать объект пошагово:

```cs
Request request = new RequestBuilder()
    .WithUrl("https://example.com")
    .WithMethod("POST")
    .WithTimeout(TimeSpan.FromSeconds(30))
    .WithBody(body)
    .Build();
```

---

## Участники паттерна

- **Product** — создаваемый объект
- **Builder** — определяет шаги построения
- **ConcreteBuilder** — реализует конкретное построение
- **Director** — задаёт порядок шагов
- **Client** — выбирает строителя и получает результат

```
Client
  ↓
Director
  ↓
Builder
  ↓
Product
```

`Director` необязателен. В современных fluent API клиент часто сам вызывает методы Builder

# Классический вариант GoF

Пусть один и тот же отчёт можно построить в текстовом и HTML-формате

## Builder

```cs
public interface IReportBuilder
{
    void BuildHeader(string title);
    void BuildBody(IEnumerable<string> lines);
    void BuildFooter();

    string GetResult();
}
```

## Конкретные строители

```cs
public sealed class TextReportBuilder : IReportBuilder
{
    private readonly StringBuilder _result = new();

    public void BuildHeader(string title)
    {
        _result.AppendLine(title);
        _result.AppendLine(new string('=', title.Length));
    }

    public void BuildBody(IEnumerable<string> lines)
    {
        foreach (string line in lines)
            _result.AppendLine(line);
    }

    public void BuildFooter()
    {
        _result.AppendLine("---");
    }

    public string GetResult() => _result.ToString();
}
```

```cs
public sealed class HtmlReportBuilder : IReportBuilder
{
    private readonly StringBuilder _result = new();

    public void BuildHeader(string title)
    {
        _result.Append($"<h1>{title}</h1>");
    }

    public void BuildBody(IEnumerable<string> lines)
    {
        _result.Append("<ul>");

        foreach (string line in lines)
            _result.Append($"<li>{line}</li>");

        _result.Append("</ul>");
    }

    public void BuildFooter()
    {
        _result.Append("<footer>Report</footer>");
    }

    public string GetResult() => _result.ToString();
}
```

## Director

```cs
public sealed class ReportDirector
{
    public string Build(
        IReportBuilder builder,
        string title,
        IEnumerable<string> lines)
    {
        builder.BuildHeader(title);
        builder.BuildBody(lines);
        builder.BuildFooter();

        return builder.GetResult();
    }
}
```

## Использование

```cs
var director = new ReportDirector();

string textReport = director.Build(
    new TextReportBuilder(),
    "Users",
    ["Alice", "Bob"]);

string htmlReport = director.Build(
    new HtmlReportBuilder(),
    "Users",
    ["Alice", "Bob"]);
```

Процесс построения одинаковый, но итоговое представление разное

# Fluent Builder

В современном C# Builder часто реализуют как цепочку методов

```cs
public sealed class Request
{
    public required Uri Url { get; init; }
    public string Method { get; init; } = "GET";
    public TimeSpan Timeout { get; init; } =
        TimeSpan.FromSeconds(10);
    public string? Body { get; init; }
}
```

```cs
public sealed class RequestBuilder
{
    private Uri? _url;
    private string _method = "GET";
    private TimeSpan _timeout =
        TimeSpan.FromSeconds(10);
    private string? _body;

    public RequestBuilder WithUrl(string url)
    {
        _url = new Uri(url);
        return this;
    }

    public RequestBuilder WithMethod(string method)
    {
        _method = method;
        return this;
    }

    public RequestBuilder WithTimeout(TimeSpan timeout)
    {
        _timeout = timeout;
        return this;
    }

    public RequestBuilder WithBody(string body)
    {
        _body = body;
        return this;
    }

    public Request Build()
    {
        if (_url is null)
            throw new InvalidOperationException(
                "URL is required");

        return new Request
        {
            Url = _url,
            Method = _method,
            Timeout = _timeout,
            Body = _body
        };
    }
}
```

Использование:

```cs
Request request = new RequestBuilder()
    .WithUrl("https://example.com")
    .WithMethod("POST")
    .WithBody("{}")
    .Build();
```

Возврат `this` позволяет вызывать методы цепочкой:

```cs
builder
    .WithUrl(...)
    .WithMethod(...)
    .WithBody(...);
```

# Где должна находиться валидация

Builder может проверять отдельные значения при их установке:

```cs
public RequestBuilder WithTimeout(TimeSpan timeout)
{
    if (timeout <= TimeSpan.Zero)
        throw new ArgumentOutOfRangeException(
            nameof(timeout));

    _timeout = timeout;
    return this;
}
```

Полная проверка готовности обычно выполняется в `Build()`:

```cs
public Request Build()
{
    if (_url is null)
        throw new InvalidOperationException(
            "URL is required");

    return new Request
    {
        Url = _url,
        Method = _method
    };
}
```

После `Build()` должен получаться корректный объект

# Повторное использование Builder

Builder может сбрасывать состояние после `Build()` либо оставаться настроенным для создания похожих объектов

```cs
var builder = new RequestBuilder()
    .WithUrl("https://example.com")
    .WithTimeout(TimeSpan.FromSeconds(10));

Request first = builder
    .WithMethod("GET")
    .Build();

Request second = builder
    .WithMethod("POST")
    .WithBody("{}")
    .Build();
```

Такое повторное использование допустимо, но требует понятной семантики состояния. Часто безопаснее создавать новый Builder для каждого объекта

# Примеры в .NET

## `StringBuilder`

```cs
string text = new StringBuilder()
    .Append("Hello")
    .Append(' ')
    .Append("world")
    .ToString();
```

Пошагово создаёт строковое представление. Это Builder по общей идее, хотя не полная классическая структура GoF

## ASP.NET Core

```cs
WebApplicationBuilder builder =
    WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddAuthentication();

WebApplication app = builder.Build();
```

`WebApplicationBuilder` накапливает конфигурацию приложения, сервисов и хоста, после чего `Build()` создаёт `WebApplication`

## EF Core

```cs
var builder =
    new DbContextOptionsBuilder<AppDbContext>();

builder
    .UseNpgsql(connectionString)
    .EnableDetailedErrors();

DbContextOptions<AppDbContext> options =
    builder.Options;
```

## Confluent.Kafka

```cs
IProducer<string, string> producer =
    new ProducerBuilder<string, string>(config)
        .SetValueSerializer(serializer)
        .SetErrorHandler(handler)
        .Build();
```

`ProducerBuilder` и `ConsumerBuilder` накапливают конфигурацию и создают готовый Kafka-клиент
