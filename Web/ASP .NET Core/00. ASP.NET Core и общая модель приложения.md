
## 1. ASP.NET Core

**ASP.NET Core** — серверный web-фреймворк .NET для построения приложений, обрабатывающих HTTP-запросы.

Фреймворк предоставляет инфраструктуру, необходимую для создания и выполнения web-приложения:

- конфигурация приложения
- регистрация используемых приложением сервисов
- построение обработки HTTP-запросов
- регистрация доступных HTTP endpoints
- запуск и остановка приложения
- доступ к окружению, конфигурации и другим инфраструктурным возможностям

Конкретные механизмы этой инфраструктуры рассматриваются отдельно. На верхнем уровне ASP.NET Core приложение можно воспринимать как **настроенную программу, принимающую HTTP-запросы, выполняющую соответствующую прикладную логику и формирующую HTTP-ответы**.

---

## 2. Построение приложения

Типичное ASP.NET Core приложение начинается с двух основных объектов:

```cs
var builder = WebApplication.CreateBuilder(args);

var app = builder.Build();
```

Их роли различаются:

```
1. WebApplication.CreateBuilder()
     ↓
2. WebApplicationBuilder
     ↓
3. конфигурация инфраструктуры
     ↓
4. Build()
     ↓
5. WebApplication
     ↓
6. конфигурация HTTP-приложения
     ↓
7. Run()
     ↓
8. приложение принимает и обрабатывает запросы
```

Таким образом, жизненный цикл приложения концептуально разделён на фазы:

1. `Configuration`
2. `Build`
3. `Execution`

До `Build()` определяется, из чего должно состоять приложение и как оно должно быть настроено.

После `Build()` существует готовый объект приложения, который можно дополнительно настроить как HTTP-приложение и затем запустить.

---

# 3. `WebApplicationBuilder`

**`WebApplicationBuilder`** — объект, используемый для построения и конфигурации будущего ASP.NET Core приложения.

Создаётся через:

```cs
var builder = WebApplication.CreateBuilder(args);
```

Концептуально:

```
WebApplicationBuilder
│
├── Services
├── Configuration
├── Logging
├── Environment
├── Host
├── WebHost
│
└── Build()
        ↓
 WebApplication
```

Через него на этапе построения приложения доступны различные направления конфигурации:

- `Services`           — сервисы приложения (зарегистрированные зависимости)
- `Configuration` — конфигурационные данные
- `Logging`             — инфраструктура логирования
- `Environment`     — информация об окружении
- `Host`                   — конфигурация host
- `WebHost`             — web-specific конфигурация

Задача `WebApplicationBuilder` — собрать конфигурацию, необходимую для создания приложения.

Вызов:

```cs
var app = builder.Build();
```

завершает эту фазу и создаёт `WebApplication`.

---

# 4. `WebApplication`

**`WebApplication`** — объект, представляющий построенное ASP.NET Core приложение.

```cs
WebApplication app = builder.Build();
```

После создания через него выполняется конфигурация непосредственно HTTP-приложения и его последующий запуск:

```cs
var app = builder.Build();

app.Use...();
app.Map...();

app.Run();
```

На концептуальном уровне:

```
WebApplication
│
├── конфигурация обработки HTTP-запросов
├── регистрация endpoints
├── доступ к инфраструктуре приложения
└── управление запуском и остановкой
```

Один объект объединяет несколько разных ролей ASP.NET Core приложения.

---

# 5. Основные роли `WebApplication`

`WebApplication` реализует интерфейсы:

- `IHost`
- `IApplicationBuilder`
- `IEndpointRouteBuilder`

### 5.1. `IHost`

Представляет приложение с точки зрения его **жизненного цикла**:

- запуск
- работа
- остановка

Через эту роль приложение может быть запущено, остановлено и связано с общей hosting-инфраструктурой .NET.

Основные возможности:

```cs
// Управление жизненным циклом host
await app.StartAsync();
await app.StopAsync();

// Доступ к зарегистрированным сервисам
app.Services;
```

Кроме того, с host связаны общая инфраструктура приложения и его lifecycle.

---

### 5.2. `IApplicationBuilder`

`IApplicationBuilder` представляет приложение с точки зрения **построения пайплайна обработки HTTP-запросов**.

Через него в pipeline регистрируются **middleware** — компоненты, последовательно участвующие в обработке каждого запроса:

Основные операции:

```cs
// Добавление middleware в pipeline
app.Use(...);
app.UseMiddleware<...>();

// Добавление конечного обработчика pipeline
app.Run(...);

// Ветвление pipeline
app.Map(...);
app.MapWhen(...);
app.UseWhen(...);
```

---

### 5.3. `IEndpointRouteBuilder`

`IEndpointRouteBuilder` представляет приложение с точки зрения **регистрации endpoints**

Endpoint описывает доступную приложению точку обработки HTTP-запроса. Через эту роль приложение объявляет, **какие запросы оно умеет обрабатывать и каким обработчикам они соответствуют**.

Основные возможности:

```cs
// Регистрация endpoints для HTTP-методов
app.MapGet(...);
app.MapPost(...);
app.MapPut(...);
app.MapDelete(...);
app.MapMethods(...);

// Группировка endpoints
app.MapGroup(...);

// Регистрация endpoints Controllers
app.MapControllers();
```

---

# 6. Общая структура программы

Минимальное ASP.NET Core приложение можно представить следующим образом:

```cs
var builder = WebApplication.CreateBuilder(args);

// конфигурация будущего приложения

var app = builder.Build();

// конфигурация HTTP-приложения

app.Run();
```

> **`WebApplicationBuilder` отвечает за построение и конфигурацию будущего приложения, а `WebApplication` представляет построенное приложение и объединяет его основные роли: lifecycle, конфигурацию обработки HTTP-запросов и регистрацию endpoints.**
