# 1. Конкурентность

**Конкурентность** — это организация выполнения нескольких задач так, что их выполнение перекрывается во времени

Задачи могут выполняться:

- поочерёдно на одном ядре
- одновременно на нескольких ядрах

Параллелизм — частный случай конкурентности, при котором задачи выполняются физически одновременно.


**Конкурентный доступ** — это обращение нескольких потоков или задач к одному общему ресурсу с перекрытием во времени

Если хотя бы один участник изменяет ресурс, без синхронизации возможны:

- гонки данных
- потеря изменений
- чтение несогласованного состояния
- нарушение инвариантов

# 2. Процессы и потоки

## 2.1. Поток

Это независимая последовательность выполнения инструкций внутри процесса, которую планировщик ОС назначает на логический процессор.

У каждого потока есть собственные:

- стек
- значения регистров
- состояние планирования
- thread-local данные

Поток принадлежит процессу.

В .NET объект `Thread` представляет абстракцию над потоком ОС. Несколько потоков могут выполняться конкурентно, а при наличии нескольких логических процессоров — параллельно.

#### Состояния потока:

- Ready           - готов к выполнению
- Running        - выполняется
- Wait              - ожидает
- Suspended  - приостановлен, не планируется и не тратит ресурсы
- Resume        - восстановлен
- Stopped       - остановлен в моменте выполнения или ожидания

#### Приоритеты и фоновые потоки

- каждый поток имеет свой приоритет - более приоритетный планируется активнее
- разделяются на **foreground** (удерживает процесс запущенным) и **background** (не удерживает)
- стартовый поток в процессе - всегда **foreground**

## 2.2 Процесс

Это абстракция ОС, представляющая запущенный экземпляр программы и объединяющая её ресурсы

Процесс имеет:

- собственное виртуальное адресное пространство
- минимум один поток
- код программы и загруженных библиотек
- статические данные
- кучи
- открытые файлы, сокеты и другие системные ресурсы
- идентификатор процесса
- переменные окружения и рабочий каталог
- контекст безопасности

# 4. Синхронизация доступа

Синхронизация нужна для согласованной работы потоков с общими изменяемыми данными.

---
## 4.1. Способы избежать гонок:

### 1. Эксклюзивный доступ

В каждый момент с ресурсом работает только один поток, остальные ожидают освобождения ресурса.

Для этого используются `lock`, `Monitor`, `Mutex`, `SemaphoreSlim` и другие примитивы синхронизации.

### 2. Lock-free алгоритмы

Потоки работают без программной блокировки, используя атомарные операции. 
При конфликте неудачная операция повторяется на основе нового состояния.

Основные средства в .NET — методы класса `Interlocked`.

### 3. Передача владения ресурсом

Ресурс принадлежит только одному потоку, который самостоятельно выполняет все операции над ним, другие потоки не обращаются к ресурсу напрямую, а передают владельцу сообщения или команды через потокобезопасную очередь или канал.

## 4.3. Примитивы синхронизации уровня ядра

### 1. `Mutex`

Предоставляет эксклюзивный доступ одному потоку

```cs
using var mutex = new Mutex()

mutex.WaitOne()

try
{
    // критическая секция
}
finally
{
    mutex.ReleaseMutex()
}
```

Особенности:

- одновременно владеет только один поток
- освобождать должен поток-владелец
- поддерживает повторный захват тем же потоком
- именованный `Mutex` может синхронизировать разные процессы
- аварийное завершение владельца может привести к `AbandonedMutexException`

### 2. `Semaphore`

Хранит счётчик разрешений и допускает одновременно несколько потоков

```cs
using var semaphore = new Semaphore(2, 2)

semaphore.WaitOne()

try
{
    // одновременно выполняются не более двух потоков
}
finally
{
    semaphore.Release()
}
```

Особенности:

- не имеет понятия владельца
- один поток может освободить разрешение, полученное другим
- `Release()` увеличивает количество доступных разрешений
- именованный `Semaphore` может использоваться между процессами

## 4.4 Примитивы синхронизации пользовательского уровня


### 1. `SpinWait`

- структура
- выполняет пустую процессорную инструкцию
- если выполнил их слишком много раз, переключает контекст, отдавая свой квант другому потоку
- на одноядерных машинах сразу прерывает выполнение потока, ибо освободить ресурм все равно должен другой поток
- используется почти во всех гибридах

#### Основные методы

```cs
public void SpinOnce()
// Выполняет один шаг адаптивного ожидания

public bool NextSpinWillYield { get }
// Показывает, будет ли следующий шаг уступать процессор

public int Count { get }
// Количество выполненных шагов ожидания

public void Reset()
// Сбрасывает состояние SpinWait

public static bool SpinUntil(Func<bool> condition)
// Ожидает, пока условие не станет истинным
```

#### Пример

```cs
private bool _ready

public void WaitUntilReady()
{
    SpinWait spinner = new SpinWait()

    while (!Volatile.Read(ref _ready))
    {
        spinner.SpinOnce()
    }
}
```


### 2. `SpinLock`

- структура
- под капотом `SpinWait`
- блокирует по объекту
- редко используется
#### Основные методы

```cs
public void Enter(ref bool lockTaken)
// Ожидает захвата и записывает результат в lockTaken

public void TryEnter(ref bool lockTaken)
// Пытается захватить блокировку без длительного ожидания

public void TryEnter(int millisecondsTimeout, ref bool lockTaken)
// Пытается захватить блокировку с ограничением времени

public void Exit()
// Освобождает блокировку

public bool IsHeld { get }
// Показывает, захвачена ли блокировка
```

#### Пример

```cs
private SpinLock _spinLock
private int _value

public void Increment()
{
    bool lockTaken = false

    try
    {
        _spinLock.Enter(ref lockTaken)
        _value++
    }
    finally
    {
        if (lockTaken)
            _spinLock.Exit()
    }
}
```


### 3. `Interlocked`

- предоставляет атомарные операции над отдельными переменными
- `CompareExchange` широко используется в конкурентных коллекциях
- JIT заменяет операции машинными атомарными инструкциями для конкретного процессора

#### Основные методы

```cs
public static int Increment(ref int location)
// Атомарно увеличивает значение на 1 и возвращает новый результат

public static int Decrement(ref int location)
// Атомарно уменьшает значение на 1 и возвращает новый результат

public static int Add(ref int location, int value)
// Атомарно прибавляет value и возвращает новый результат

public static int Exchange(ref int location, int value)
// Атомарно записывает value и возвращает предыдущее значение

public static int CompareExchange(
    ref int oldValue,
    int newValue,
    int valueToCompare
)
// Если oldValue == valueToCompare, атомарно записывает newValue
// В любом случае возвращает предыдущее значение oldValue
```

Эти методы также имеют перегрузки для других поддерживаемых типов.

#### Пример

```cs
private int _counter

public void Increment()
{
    Interlocked.Increment(ref _counter)
}
```

## 4.5 Гибридные примитивы синхронизации

### 1. `Monitor`

Связан с конкретным ссылочным объектом

```cs
Monitor.Enter(sync)

try
{
    // критическая секция
}
finally
{
    Monitor.Exit(sync)
}
```

При захвате:

- свободный монитор получает текущий поток
- повторный вход того же потока увеличивает счётчик рекурсии
- другой поток сначала может кратко ожидать активно, затем блокируется средствами ОС

Освободить монитор может только поток-владелец

Основные методы:

```cs
Monitor.Enter(obj)       // захватить монитор
Monitor.TryEnter(obj)    // попытаться захватить
Monitor.Exit(obj)        // освободить монитор
Monitor.Wait(obj)        // освободить монитор и ждать сигнал
Monitor.Pulse(obj)       // уведомить один ожидающий поток
Monitor.PulseAll(obj)    // уведомить все ожидающие потоки
```

`Wait`, `Pulse` и `PulseAll` вызываются только потоком, уже владеющим монитором

#### Хранение состояния

CLR может использовать служебный заголовок объекта для хранения компактного состояния блокировки:

При конкуренции или нехватке места создаётся внешняя структура синхронизации `SyncBlock`, а заголовок хранит ссылку или индекс на неё

Точная реализация является внутренней деталью CLR


### 2. `lock`

Обычный `lock` над ссылочным объектом — синтаксический сахар над `Monitor`

```cs
private readonly object _sync = new()

lock (_sync)
{
    // критическая секция
}
```

Компилятор разворачивает его примерно так:

```cs
bool lockTaken = false

try
{
    Monitor.Enter(_sync, ref lockTaken)

    // критическая секция
}
finally
{
    if (lockTaken)
        Monitor.Exit(_sync)
}
```

Свойства обычного `lock`:

- обеспечивает эксклюзивный доступ
- является рекурсивным
- блокирует поток при длительном ожидании
- внутри нельзя использовать `await`
- объект синхронизации должен быть приватным и неизменяемым


### 3. `SemaphoreSlim`

Гибридный примитив, ограничивающий количество потоков или задач, которые могут одновременно работать с ресурсом

Хранит счётчик доступных разрешений

```cs
private readonly SemaphoreSlim _semaphore = new(
    initialCount: 3,
    maxCount: 3
)
```

Особенности:

- поддерживает синхронное и асинхронное ожидание
- при коротком синхронном ожидании может использовать активное вращение
- при длительном ожидании блокирует поток на уровне ОС
- `WaitAsync()` не блокирует поток
- не имеет владельца
- работает только внутри одного процесса

#### Основные методы

```cs
public void Wait()
// Синхронно ожидает и забирает одно разрешение

public bool Wait(int millisecondsTimeout)
// Ожидает разрешение ограниченное время

public Task WaitAsync()
// Асинхронно ожидает и забирает одно разрешение

public Task<bool> WaitAsync(int millisecondsTimeout)
// Асинхронно ожидает разрешение ограниченное время

public int Release()
// Возвращает одно разрешение

public int Release(int releaseCount)
// Возвращает несколько разрешений

public int CurrentCount { get }
// Возвращает текущее количество свободных разрешений
```

#### Пример

```cs
using var semaphore = new SemaphoreSlim(2, 2);

async Task ProcessAsync(int id)
{
    Console.WriteLine($"Задача {id} ожидает разрешение");

    await semaphore.WaitAsync();

    try
    {
        Console.WriteLine($"Задача {id} вошла");

        await Task.Delay(2000);

        Console.WriteLine($"Задача {id} выходит");
    }
    finally
    {
        semaphore.Release();
    }
}

var tasks = new List<Task>();

for (int i = 1; i <= 5; i++)
    tasks.Add(ProcessAsync(i));

await Task.WhenAll(tasks);
```


### 4. `ReaderWriterLockSlim`

- Разделяет читающую и пишущую нагрузку
- Читать могут одновременно несколько потоков, пока данные не изменяются
- Изменять данные может только один поток
- Во время записи остальные потоки не могут ни читать, ни записывать
