Суть паттерна — **дважды проверить условие**:

- первый раз до блокировки, чтобы не захватывать `lock`, когда работа уже выполнена
- второй раз внутри блокировки, потому что другой поток мог выполнить работу, пока текущий ждал

```cs
private readonly object _sync = new();
private volatile SomeObject? _value;

public SomeObject GetValue()
{
    var value = _value;

    if (value is null)               // первая проверка без блокировки
    {
        lock (_sync)
        {
            value = _value;

            if (value is null)       // повторная проверка после ожидания
            {
                value = CreateValue();
                _value = value;
            }
        }
    }

    return value;
}
```

Без второй проверки два потока могли бы последовательно войти в `lock` и оба выполнить `CreateValue()`

Применяется, когда:

- создание или обновление состояния — дорогая операция
- выполнить её должен только один поток
- состояние изменяется редко, но читается часто
- после создания его желательно читать без постоянного захвата `lock`

Обычно это ленивая инициализация или редкое обновление общего состояния. Для обычных конкурентных изменений коллекций и объектов double-checked locking не предназначен.
