# События в C#

# 1. Определение

Событие — член типа, основанный на делегате и предназначенный для уведомления подписчиков о произошедшем действии

Участники:
- издатель объявляет и вызывает событие
- подписчики добавляют обработчики
- обработчик выполняется при вызове события

# 2. Объявление

~~~csharp
public event Action<string>? StatusChanged;
~~~

Тип события должен быть типом делегата

~~~csharp
public delegate void StatusChangedHandler(string status);

public event StatusChangedHandler? StatusChanged;
~~~

Само событие не является типом

`event` ограничивает доступ к лежащему в его основе делегату

# 3. Подписка и отписка

Подписка выполняется через `+=`

~~~csharp
order.StatusChanged += HandleStatusChanged;
~~~

Отписка выполняется через `-=`

~~~csharp
order.StatusChanged -= HandleStatusChanged;
~~~

Одновременно может быть подписано несколько обработчиков

Они вызываются в порядке добавления

Если обработчик выбрасывает необработанное исключение, вызов следующих обработчиков прекращается

# 4. Вызов события

Событие вызывает только тип, в котором оно объявлено

~~~csharp
StatusChanged?.Invoke("Completed");
~~~

Внешний код не может:

- вызвать событие
- присвоить ему новый делегат
- очистить все обработчики
- получить его `invocation list`

Снаружи доступны только `+=` и `-=`

# 5. Событие и обычный делегат

Открытое поле делегата:

~~~csharp
public Action<string>? StatusChanged;
~~~

позволяет внешнему коду полностью управлять делегатом

~~~csharp
order.StatusChanged = handler;
order.StatusChanged = null;
order.StatusChanged?.Invoke("Fake");
~~~

Событие:

~~~csharp
public event Action<string>? StatusChanged;
~~~

инкапсулирует делегат и разделяет права издателя и подписчиков

# 6. Стандартный шаблон .NET

Событие без дополнительных данных:

~~~csharp
public event EventHandler? Completed;
~~~

Вызов:

~~~csharp
Completed?.Invoke(this, EventArgs.Empty);
~~~

Событие с данными:

~~~csharp
public event EventHandler<StatusChangedEventArgs>? StatusChanged;

public sealed class StatusChangedEventArgs : EventArgs
{
    public string OldStatus { get; }
    public string NewStatus { get; }

    public StatusChangedEventArgs(string oldStatus, string newStatus)
    {
        OldStatus = oldStatus;
        NewStatus = newStatus;
    }
}

StatusChanged?.Invoke(
    this,
    new StatusChangedEventArgs(oldStatus, newStatus)
);
~~~

Параметры обработчика:

- `sender` — источник события
- `e` — данные события

# 7. Полевые события

Обычное объявление:

~~~csharp
public event EventHandler? Changed;
~~~

называется полевым событием

Компилятор создаёт:

- скрытое поле делегата
- аксессор добавления обработчика
- аксессор удаления обработчика

Внутри объявившего типа событие доступно почти как обычный делегат

# 8. Пользовательские `add` и `remove`

Логику подписки и отписки можно определить вручную

~~~csharp
private EventHandler? _changed;

public event EventHandler Changed
{
    add
    {
        _changed += value;
    }

    remove
    {
        _changed -= value;
    }
}
~~~

Внутри аксессоров `value` содержит добавляемый или удаляемый обработчик

Вызов выполняется через собственное хранилище:

~~~csharp
_changed?.Invoke(this, EventArgs.Empty);
~~~

Пользовательские аксессоры применяются для нестандартного хранения, журналирования или контроля подписок

# 9. События и наследование

Производный класс не может напрямую вызвать полевое событие базового класса

Обычно базовый класс предоставляет защищённый метод:

~~~csharp
public class Entity
{
    public event EventHandler? Changed;

    protected virtual void OnChanged()
    {
        Changed?.Invoke(this, EventArgs.Empty);
    }
}
~~~

Производные классы вызывают или переопределяют `OnChanged`

# 10. Анонимные обработчики

Подписываться можно анонимной функцией:

~~~csharp
order.StatusChanged += status => Console.WriteLine(status);
~~~

Для гарантированной отписки обработчик нужно сохранить:

~~~csharp
Action<string> handler = status => Console.WriteLine(status);

order.StatusChanged += handler;
order.StatusChanged -= handler;
~~~

Повторно записанная лямбда не считается тем же экземпляром обработчика

# 11. Время жизни и память

Издатель хранит делегаты обработчиков, а делегаты могут удерживать объекты подписчиков через `Target`

~~~text
издатель
    ↓
делегат обработчика
    ↓
подписчик
~~~

Если издатель живёт дольше подписчика, обработчик следует отписать

~~~csharp
publisher.Changed -= OnChanged;
~~~

Особенно осторожно нужно обращаться со статическими событиями, которые могут существовать всё время работы приложения

# 12. Потокобезопасность

События не делают обработчики потокобезопасными

Подписка, отписка и вызов могут происходить из разных потоков, поэтому общие изменяемые данные требуют отдельной синхронизации

Вызов через `?.Invoke` защищает только от вызова `null`, но не от гонок внутри обработчиков
