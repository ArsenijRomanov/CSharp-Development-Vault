# 1. Определение

Делегат — это ссылочный тип, экземпляр которого хранит один или несколько вызовов методов с определённой сигнатурой.

Делегат типобезопасен: в него можно записать только метод с совместимыми:
- типом возвращаемого значения
- количеством параметров
- типами и модификаторами параметров

---
# 2. Объявление типа делегата

~~~csharp
public delegate int Operation(int a, int b);
~~~

Это объявляет новый тип `Operation`, способный ссылаться на методы сигнатуры:

~~~csharp
int Method(int a, int b)
~~~

Каждое объявление `delegate` создаёт отдельный тип.

Делегаты с одинаковой сигнатурой всё равно являются разными типами:

~~~csharp
delegate int First(int value);
delegate int Second(int value);
~~~

`First` и `Second` — разные типы.

Тип делегата можно объявить:
- в пространстве имён
- внутри класса, структуры или интерфейса

---
# 3. Создание экземпляра

~~~csharp
static int Add(int a, int b) => a + b;

Operation operation = Add;
~~~

Эквивалентно:

~~~csharp
Operation operation = new Operation(Add);
~~~


Вызов делегата:

~~~csharp
int result = operation(2, 3);
~~~

Эквивалентно:

~~~csharp
int result = operation.Invoke(2, 3);
~~~

---
# 4. Что хранится внутри

Концептуально один вызов делегата содержит:

~~~text
Method — метод, который нужно вызвать
Target — объект, на котором нужно вызвать метод
~~~

Для статического метода:

~~~text
Method = Add
Target = null
~~~

Для экземплярного метода:

~~~csharp
var calculator = new Calculator();
Operation operation = calculator.Add;
~~~

делегат хранит:

~~~text
Method = Calculator.Add
Target = calculator
~~~

Поэтому делегат на экземплярный метод удерживает целевой объект в памяти.

---
# 5. Ссылочный тип

Делегаты являются ссылочными типами:

~~~text
System.Object
    └── System.Delegate
          └── System.MulticastDelegate
                └── Operation
~~~

Переменная делегата может содержать `null`:

~~~csharp
Operation? operation = null;
~~~

Вызов `null` приведёт к `NullReferenceException`.

---
# 6. Иммутабельность

Объекты делегатов неизменяемы.

Добавление или удаление метода не изменяет существующий делегат, а создаёт новый:

~~~csharp
operation += Multiply;
~~~

Примерно эквивалентно:

~~~csharp
operation = (Operation)Delegate.Combine(operation, Multiply);
~~~


А удаление:

~~~csharp
operation -= Multiply;
~~~

примерно эквивалентно:

~~~csharp
operation = (Operation?)Delegate.Remove(operation, Multiply);
~~~

Операторы `+=` и `-=` выполняют операцию и переприсваивают переменной новую ссылку.

---
# 7. Invocation list

Делегат может содержать несколько вызовов.

Их упорядоченный список называется `invocation list`.

~~~csharp
Operation operation = Add;
operation += Multiply;
~~~

Теперь список выглядит так:

~~~text
Add
Multiply
~~~

При вызове методы выполняются в порядке добавления.

Получить список:

~~~csharp
Delegate[] methods = operation.GetInvocationList();
~~~

Каждый элемент списка представляет отдельный вызов со своими `Method` и `Target`.

---
# 8. Операторы

## 8.1. Присваивание

Заменяет весь список вызовов:

~~~csharp
operation = Add;
operation = Multiply;
~~~

После второй строки остаётся только `Multiply`.

## 8.2. Добавление

~~~csharp
operation += Multiply;
~~~

Добавляет метод в конец списка.

Один метод можно добавить несколько раз — он будет вызван несколько раз.

## 8.3. Удаление

~~~csharp
operation -= Multiply;
~~~

Удаляет последнее подходящее вхождение из списка.

Если удалён последний метод, результатом становится `null`.

## 8.4. Объединение

~~~csharp
Operation combined = first + second;
~~~

Создаёт делегат с объединёнными списками вызовов.

## 8.5. Вычитание

~~~csharp
Operation? result = first - second;
~~~

Создаёт новый делегат без последнего совпадающего списка вызовов `second`.

---
# 9. Возвращаемое значение multicast-делегата

Если делегат содержит несколько методов с возвращаемым значением, вызываются все методы, но наружу возвращается результат последнего:

~~~csharp
Operation operation = Add;
operation += Multiply;

int result = operation(2, 3);
~~~

`Add` вернёт `5`, `Multiply` вернёт `6`, итоговый `result` будет равен `6`.

---
# 10. Исключения

Если один метод из `invocation list` выбрасывает исключение, обычный вызов прекращается.

Оставшиеся методы не выполняются.

Для независимой обработки каждого вызова нужно вручную перебрать `GetInvocationList()`.

---
# 11. Сравнение

Хотя делегаты являются ссылочными типами, `==` сравнивает их по содержимому.

Делегаты равны, если у них совпадают:

- тип делегата
- методы
- целевые объекты
- порядок элементов `invocation list`

~~~csharp
Operation first = calculator.Add;
Operation second = calculator.Add;

Console.WriteLine(first == second); // true
~~~

`ReferenceEquals` при этом проверяет именно идентичность объектов.

# 12. Основные члены делегата

У экземпляра делегата доступны:

~~~csharp
operation.Invoke(...)
~~~
Вызывает `invocation list`.

~~~csharp
operation.GetInvocationList()
~~~
Возвращает отдельные вызовы списка.

~~~csharp
operation.Method
~~~
Информация о методе последнего элемента делегата.

~~~csharp
operation.Target
~~~
Целевой объект последнего элемента либо `null` для статического метода.

~~~csharp
operation.DynamicInvoke(...)
~~~
Вызывает делегат через массив `object?[]`.

Проверка типов происходит во время выполнения, поэтому обычный `Invoke` предпочтительнее.

Статические методы класса `Delegate`:

~~~csharp
Delegate.Combine(...)
Delegate.Remove(...)
~~~

Операторы `+` и `-` основаны на этих операциях.

# 13. Ковариантность и контрвариантность

Ковариантность и контрвариантность позволяют использовать совместимые ссылочные типы вместо точного совпадения типов

## 13.1. Совместимость метода с делегатом

### Ковариантность возвращаемого значения

Метод может возвращать более конкретный тип, чем указано в делегате

~~~csharp
class Animal { }
class Cat : Animal { }

static Cat CreateCat() => new();

Func<Animal> factory = CreateCat;
~~~

`CreateCat` возвращает `Cat`, который можно использовать как `Animal`

### Контрвариантность параметров

Метод может принимать более общий тип, чем указано в делегате

~~~csharp
static void HandleAnimal(Animal animal)
{
}

Action<Cat> handler = HandleAnimal;
~~~

`HandleAnimal` способен принять любой `Animal`, следовательно, способен принять и `Cat`

## 13.2. Вариантность обобщённых делегатов

Параметр типа делегата можно объявить ковариантным через `out`

~~~csharp
delegate TResult Producer<out TResult>();
~~~

Это разрешает преобразование от более конкретного типа к более общему:

~~~csharp
Producer<Cat> catProducer = CreateCat;
Producer<Animal> animalProducer = catProducer;
~~~

Параметр типа можно объявить контрвариантным через `in`

~~~csharp
delegate void Consumer<in T>(T value);
~~~

Это разрешает преобразование от более общего типа к более конкретному:

~~~csharp
Consumer<Animal> animalConsumer = HandleAnimal;
Consumer<Cat> catConsumer = animalConsumer;
~~~

Стандартные делегаты уже объявлены вариантными:

~~~csharp
Func<out TResult>
Action<in T>
Func<in T, out TResult>
~~~

Поэтому допустимы преобразования:

~~~csharp
Func<Cat> catFactory = CreateCat;
Func<Animal> animalFactory = catFactory;

Action<Animal> animalHandler = HandleAnimal;
Action<Cat> catHandler = animalHandler;
~~~

## 13.3. Ограничения

Вариантность работает только для ссылочных типов:

~~~csharp
Func<int> intFactory = () => 10;

// Ошибка
Func<object> objectFactory = intFactory;
~~~

Преобразование возможно только между экземплярами одного обобщённого типа делегата:

~~~csharp
delegate Animal First();
delegate Animal Second();
~~~

`First` и `Second` не преобразуются друг в друга автоматически, даже если имеют одинаковую сигнатуру

Вариантность не применяется к параметрам `ref`, `in` и `out` методов — для них требуется точное соответствие типов и модификаторов

Модификаторы обобщённых параметров `in` и `out` не следует путать с модификаторами параметров методов:

~~~csharp
delegate void Consumer<in T>(T value);
delegate bool Parser(string text, out int result);
~~~

В первом случае `in` обозначает контрвариантность типа `T`

Во втором случае `out` обозначает передачу параметра по ссылке с обязательным присваиванием результата
