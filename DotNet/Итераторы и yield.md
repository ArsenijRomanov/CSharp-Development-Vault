# 1. Итератор

**Итератор** — объект, который последовательно выдаёт элементы коллекции или вычисляемой последовательности

Перебор выполняется через:

- `MoveNext()` — переходит к следующему элементу
- `Current` — возвращает текущий элемент
- `Dispose()` — освобождает ресурсы

Цикл `foreach` использует эти члены автоматически

---

# 2. Интерфейсы перечисления

`IEnumerable<T>` представляет объект, который умеет создавать перечислители:

```csharp
public interface IEnumerable<out T>
{
    IEnumerator<T> GetEnumerator()
}
```

`IEnumerator<T>` представляет один конкретный процесс перебора:

```csharp
public interface IEnumerator<out T> : IDisposable
{
    T Current { get }
    bool MoveNext()
    void Reset()
}
```

Главное различие:

```
IEnumerable<T>  — последовательность
IEnumerator<T> — один проход по последовательности
```

---

# 3. Итераторный метод

Итераторный метод содержит `yield` и возвращает один из типов:

- `IEnumerable<T>`
- `IEnumerator<T>`
- `IEnumerable`
- `IEnumerator`

Обычно используется `IEnumerable<T>`

```csharp
static IEnumerable<int> GetNumbers()
{
    yield return 10;
    yield return 20;
}
```

---

# 4. `yield return`

`yield return` выдаёт очередной элемент и приостанавливает выполнение метода:

```
yield return value;
```

При следующем вызове `MoveNext()` выполнение продолжается с инструкции после `yield return`

Каждый `yield return`:

- записывает значение в `Current`
- сохраняет точку продолжения
- возвращает `true` из `MoveNext()`
- приостанавливает выполнение

---

# 5. `yield break`

`yield break` немедленно завершает перебор:

```
if (condition)
    yield break;
```

После него `MoveNext()` возвращает `false`

Обычное достижение конца итераторного метода даёт тот же результат

В итераторе нельзя вернуть значение через обычный `return`

> Тело итераторного метода обычно не выполняется при его вызове.
> Выполнение начинается при запросе элементов, поэтому вычисления происходят по мере перебора, а не заранее.
> Если перебор прекращён раньше, оставшаяся часть метода не выполняется.

# 6. Преобразование компилятором

Компилятор преобразует итераторный метод в скрытый класс-конечный автомат

Он содержит примерно такие поля:

```
state   — текущее состояние выполнения
current — текущий элемент
```

И реализует `MoveNext()` примерно так:

```
public bool MoveNext()
{
    switch (_state)
    {
        case 0:
            _current = 10;
            _state = 1;
            return true;

        case 1:
            _current = 20;
            _state = -1;
            return true;

        default:
            return false;
    }
}
```

Точная структура сгенерированного кода не гарантируется

# 7. Состояние итератора

Компилятор создаёт состояния для точек, после которых выполнение должно продолжиться

Обычно каждой точке `yield return` соответствует отдельное продолжение

Цикл не создаёт новое состояние для каждой итерации:

```cs
for (int i = 0; i < count; i++)
{
    yield return i;
}
```

Здесь используется одна точка `yield return`, а значение `i` сохраняется между вызовами `MoveNext()`

Локальные переменные и параметры, необходимые после приостановки, становятся полями объекта итератора

---

# 8. `IEnumerable<T>` и `IEnumerator<T>`

Если метод возвращает `IEnumerable<T>`, результат представляет последовательность:

```cs
IEnumerable<int> numbers = GetNumbers();
```

Каждый новый перебор получает отдельный `IEnumerator<T>` со своим состоянием

Если метод возвращает `IEnumerator<T>`, результат представляет уже начатый объект одного перебора:

```cs
IEnumerator<int> enumerator = GetEnumerator();
```

С ним работают напрямую через `MoveNext()` и `Current`

Для `IEnumerable<T>` компилятор часто создаёт класс, реализующий одновременно `IEnumerable<T>` и `IEnumerator<T>`

---

# 9. Завершение и освобождение ресурсов

`foreach` вызывает `Dispose()` у перечислителя, даже если перебор завершён досрочно

Поэтому блок `finally` внутри итератора выполняется при:

- полном завершении перебора
- `yield break`
- исключении
- досрочном прекращении `foreach`

`yield return` разрешён внутри `try`, если у него есть `finally`, но нет `catch`

---

# 10. Ограничения

Итераторный метод не может:

- иметь параметры `ref`, `in` или `out`
- возвращать значение через обычный `return`
- использовать `yield return` внутри `catch`
- использовать `yield return` внутри `finally`
- использовать `yield return` внутри `try`, у которого есть `catch`

`yield` нельзя использовать внутри вложенной лямбды или анонимного метода — такая функция должна быть отдельным итератором
