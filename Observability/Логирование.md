Лог — некоторое сообщение с информацией о том, что происходило в вашем приложении.

Лог может храниться как в обычном текстовом файле (WAL, systemd-journald), так и в какой-либо базе данных.

# 1. Логирование в .NET

В .NET есть стандартная абстракция логирования — **`Microsoft.Extensions.Logging`**, которая включает в себя интерфейсы:

### 1.1. `ILogger`, `ILogger<T>`

 Базовая абстракция логгера.
 
Упрощённо он содержит три основные операции:

```cs
public interface ILogger
{
    void Log<TState>(
        LogLevel logLevel,
        EventId eventId,
        TState state,
        Exception? exception,
        Func<TState, Exception?, string> formatter);

    bool IsEnabled(LogLevel logLevel);

    IDisposable? BeginScope<TState>(TState state);
}
```

На практике низкоуровневый `Log` почти всегда используется через extension-методы:

```cs
_logger.LogTrace("...");
_logger.LogDebug("...");
_logger.LogInformation("...");
_logger.LogWarning("...");
_logger.LogError("...");
_logger.LogCritical("...");
```

`BeginScope` создаёт логический контекст для группы связанных логов

```cs
using (_logger.BeginScope(
    new Dictionary<string, object>
    {
        ["OrderId"] = orderId,
        ["UserId"] = userId
    }))
{
    _logger.LogInformation("Order validation started");
    _logger.LogInformation("Payment started");
}
```

Если provider поддерживает scopes, значения из scope добавляются ко всем логам внутри блока

Это удобно для общего контекста операции: `RequestId`, `OrderId`, `UserId`, `CorrelationId` и т.д.

### 1.2. `ILoggerFactory`

Конфигурирует систему логирования, создаёт инстанс `Ilogger`, регистрирует `ILoggerProvider`.

### 1.3. `ILoggerProvider`

Абстракция конкретного provider:

```cs
public interface ILoggerProvider : IDisposable
{
    ILogger CreateLogger(string categoryName);
}
```

Создает объект, реализующий `ILogger` 

### 1.4. `ILoggingBuilder`

Используется при **конфигурации logging pipeline**

Через него регистрируются providers и фильтры:

```cs
builder.Logging
    .ClearProviders()
    .AddConsole()
    .AddDebug();
```

`ILoggingBuilder` предоставляет доступ к `IServiceCollection`, в котором настраивается logging infrastructure.

# 2. Уровни логирования

| Log Level | Severity | Extension Method | Description |
|---|---:|---|---|
| Trace | 0 | `LogTrace()` | Логирует сообщения только для трассировки, предназначенные для разработчиков |
| Debug | 1 | `LogDebug()` | Логирует сообщения для краткосрочной отладки |
| Information | 2 | `LogInformation()` | Логирует сообщения о ходе выполнения приложения |
| Warning | 3 | `LogWarning()` | Логирует сообщения о ненормальных или неожиданных событиях в ходе выполнения приложения |
| Error | 4 | `LogError()` | Логирует сообщения об ошибках |
| Critical | 5 | `LogCritical()` | Логирует сообщения о сбоях, требующих немедленного внимания |

# 3. Структурированное логирование

Пишется через шаблон сообщения и отдельные параметры:

```cs
_logger.LogInformation(
    "Order {OrderId} created by user {UserId}",
    orderId,
    userId);
```

Вместо:

```cs
_logger.LogInformation(
    $"Order {orderId} created by user {userId}");
```

Смысл в том, что `OrderId` и `UserId` сохраняются как отдельные поля, а не только как часть строки

Это нужно, чтобы потом в системе хранения логов можно было нормально искать и фильтровать:

```
OrderId = 42
UserId = 15
Level = Error
```

- ﻿﻿Логирование в stdout

# 5. Сторонние logging providers

Помимо встроенных providers, в .NET часто используют сторонние logging frameworks — прежде всего **Serilog** и **NLog**. Они интегрируются с `Microsoft.Extensions.Logging`, поэтому код приложения продолжает работать через обычный `ILogger<T>`

```
ILogger<T>
→ Serilog / NLog
→ обработка логов
→ Console / File / Seq / Elasticsearch / ...
```

Они дают более развитый logging pipeline: **структурирование, enrichment, фильтрацию, форматирование, маршрутизацию и дополнительные destinations**. 

- **Serilog** — ориентирован на structured logging, enrichment и удобную конфигурацию pipeline; destinations называются **sinks**
- **NLog** — делает акцент на гибких правилах фильтрации и маршрутизации; destinations называются **targets**

# 6. Хранилища и платформы для логов

**Хранилища логов** — системы, оптимизированные под большой поток append-only событий, поиск по времени и полям, сжатие и retention

Примеры:

- **Elasticsearch / OpenSearch** — индексирование и гибкий поиск по содержимому логов
- **ClickHouse** — колоночная БД, часто используемая для больших объёмов логов и аналитики

Поверх хранилищ могут использоваться **log management platforms** — готовые системы для централизованной работы с логами

- **Graylog** — принимает и обрабатывает логи, маршрутизирует их, предоставляет поиск, dashboards и alerts, а хранение делегирует search/storage backend
- **Elastic Stack** — Elasticsearch для хранения + Kibana для поиска и визуализации + компоненты доставки/обработки
- **Seq** — платформа для хранения, поиска и анализа структурированных логов, особенно распространённая в .NET
