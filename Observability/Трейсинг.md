
**Distributed tracing** — механизм, позволяющий проследить путь одного запроса через несколько сервисов и понять, где он провёл время и где произошла ошибка.

Основные сущности:

- `Trace` — вся операция целиком
- `Span` — отдельный участок работы внутри trace

Все spans одного запроса связаны общим `TraceId`, каждый span имеет свой `SpanId` и обычно ссылку на родительский span

### Трейсинг в .NET

Базовый API встроен в .NET:

- `ActivitySource` — создаёт `Activity` 
- `Activity` — представляет `Span`

Часть инфраструктуры .NET уже инструментирована, например `HttpClient`, поэтому многие spans можно получать автоматически.

### OpenTelemetry

**OpenTelemetry** — стандартный слой сбора и экспорта telemetry

Для tracing обычно подключаются instrumentation-библиотеки:

```cs
builder.Services
    .AddOpenTelemetry()
    .WithTracing(tracing =>
    {
        tracing
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddSource("Orders")
            .AddOtlpExporter();
    });
```

`AspNetCoreInstrumentation` создаёт spans для входящих запросов, `HttpClientInstrumentation` — для исходящих, а `AddSource` подключает наши `ActivitySource`.

### Передача trace между сервисами

Контекст trace передаётся вместе с сетевым запросом:

```
Service A
→ traceparent header
→ Service B
→ Service C
```

Благодаря этому spans из разных процессов можно собрать в один trace

### Общий pipeline

```
.NET application
→ Activity / instrumentation
→ OpenTelemetry SDK
→ OTLP
→ OpenTelemetry Collector
→ tracing backend
→ UI
```

**OTLP** — протокол передачи OpenTelemetry telemetry

**OpenTelemetry Collector** — отдельный сервис, который принимает telemetry и строит pipeline:

Он может делать batching, filtering, sampling, enrichment и отправлять данные в нужный backend.

### Хранение и UI

Типичные варианты:

```
Tempo
→ хранение traces
→ Grafana UI

Jaeger 
→ tracing backend 
→ Elasticsearch / OpenSearch / Cassandra и др. 
→ Jaeger UI

Elastic
→ Elasticsearch 
→ Kibana
```

Например полный стек:

```
ASP.NET Core
→ Activity
→ OpenTelemetry
→ OTLP
→ OTel Collector
→ Tempo
→ Grafana
```

Главная идея всего tracing pipeline:

```
instrumentation
→ создаёт spans

OpenTelemetry SDK
→ собирает и экспортирует spans

Collector
→ принимает, обрабатывает и маршрутизирует

Tempo / Jaeger / Elastic
→ tracing backends

Tempo storage / Elasticsearch / OpenSearch / Cassandra / ...
→ физическое хранение traces

Grafana / Jaeger UI / Kibana
→ поиск и анализ traces
```
